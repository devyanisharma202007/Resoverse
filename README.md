# RESOVERSE

An isometric pixel-art campus for **Resonance**, the Western Music Society of
Dyal Singh College, University of Delhi.

You walk into it rather than scroll down it. There is a plaza, six buildings you
can go inside, three arcade games, a room full of instruments you can actually
play, and the society walking about in it.

**One file. No build step, no install, no account.** Open `index.html` in any
browser and it runs.

---

## What's in it

**The campus** — a plaza with a fountain and a pond, and six places to go into:
Resonance HQ, the Arcade, the Music Room, the Lounge, the Stage and the personal
rooms. A clock runs from afternoon into night; the lamps come on, the windows
light up and fireflies appear.

**The Jam Room** — six instruments you play rather than watch:

| | |
|---|---|
| Guitar, Bass | a real fretboard, plus twelve chords you can strum |
| Keys | a keyboard, letters marked on the keys |
| Drums | eight pads — kick, snare, hats, toms, ride, crash |
| Sax, Voice | breathy lead voices with vibrato |

Pick a key and a scale and the instrument lays itself out in it, so nothing a
beginner plays can sound wrong. Record a four-bar loop, play over the top,
record again — four layers and one person is a band.

**Three arcade games**, all original:

- **Reso Rush** — match-3 in Resonance tiles, six levels, cascades that multiply
- **Reso Ludo** — the traditional cross board, 2–4 seats, pass-and-play or online
- **Reso Beat** — four-lane rhythm, four tracks, with a synthesised backing band

**The society** — every member is data. Add one from inside the game and they
walk the campus that second, with a profile, a personal room, a Hall of Fame row
and a seat available at Ludo. Nobody has to open a file to add a person.

**Progression** — XP from playing, and 24 cosmetic unlocks: hats, jackets,
instrument finishes, trails, titles and new moves. All of it renders on the
character walking around, and none of it makes you better at anything.

## Nothing in here belongs to anybody else

There is not one image file and not one audio file in this project.

Every character, building, tile and piece of interface is drawn by code at
runtime. Every sound — the footsteps, the fountain, the crowd, the arcade, the
whole Jam Room — is generated by oscillators and filtered noise as it plays.
The guitar is a plucked-string physical model, not a recording of a guitar.

That was a hard requirement, not an aesthetic: it means the society can put this
online, share it, hand it to next year's committee and never owe anyone a
licence.

## Running it

Double-click `index.html`. That's it.

To put it online for free, so the society can open it on their phones:

1. Make a new repository on GitHub and upload `index.html`, `supabase-setup.sql`
   and this README.
2. Repository **Settings → Pages**.
3. Under **Source**, choose **Deploy from a branch**, branch `main`, folder `/ (root)`.
4. Save. A minute later it's live at
   `https://<your-username>.github.io/<repository-name>/`.

Send that link to anybody. No install, no account, nothing to sign up for.

### Controls

| | Keyboard | Touch |
|---|---|---|
| Walk | `W A S D` / arrows | drag the left half of the screen |
| Run | `Shift` | push the stick further out |
| Interact | `E` or `Space` | the ✋ button |
| Chat | `Enter` | the chat box, bottom left |
| Map | `M` | the ◉ button |
| Close | `Esc` | the ✕ |

There is a full guide inside the game — the **?** button — so nobody has to be
told any of this.

## Three ways to run it

**1. Open the file.** Double-click `index.html`. Works with no internet at all.
Single-player.

**2. GitHub Pages.** The steps above. A public URL, no accounts, works on every
phone. Single-player unless you do step 3.

**3. GitHub Pages plus a free Supabase project — the shared world.**

This is the one to give the society. Five minutes, no cost, and nobody has to
sign up for anything:

1. [supabase.com](https://supabase.com) → new project (free tier is enough).
2. **SQL Editor → New query** → paste in `supabase-setup.sql` → **Run**.
3. **Project Settings → API** → copy the **Project URL** and the **anon** key.
4. Open `index.html`, find `RV_CONFIG` (search for it — it's near the bottom),
   and paste them in:

   ```js
   const RV_CONFIG = {
     supabaseUrl: 'https://yourproject.supabase.co',
     supabaseKey: 'eyJhbGciOi...',
   };
   ```
5. Commit. That's it.

Now the GitHub Pages link has everything:

- one person to a character — claim Juman and Juman is greyed out for everyone else
- you see each other walking the campus in real time
- live chat, and the Jam Room becomes a live jam: everyone hears what you play
- Reso Ludo across devices at one table
- the roster, the event board and the leaderboards are shared

The anon key is meant to be public — it identifies the project, it is not a
password. **The `service_role` key is a password.** Never put that in this file
or anywhere a browser can see it.

Be clear-eyed about the policies in the SQL: anybody who can open the page can
write to that table. For a society's game world with no personal data in it,
that is the right trade for "nobody has to make an account". If you ever put
something in there you would mind a stranger changing, add Supabase Auth and
tighten the policies — the game's code will not need touching.

### And the Claude link?

The link shared from Claude has the same shared world, running on Claude's own
infrastructure instead. The difference is that opening it requires a Claude
account, so it's right for you and a few people and wrong for forty freshers.
The Supabase copy needs nothing from anybody.

## Adding a member without touching the code

Open the game → **Society** → *Add a member*. Name, role, title, hometown, a
line about them, then skin, hair, outfit, colours and extras, with a live
preview that animates as you change it. Save and they are on the campus.

You can edit anybody this way, founders included. Editing an original writes an
override under the same id, so their scores and claims survive it, and there is
a "Back to the original" button that undoes it.

If you would rather add people in the code, the roster is a plain array near the
top of the file:

```js
const SEED_MEMBERS = [
  { id: 'riya', name: 'Riya', role: 'guitarist', title: 'Lead Guitar',
    hometown: 'Pune', tagline: 'Plays loud, tunes never.',
    bio: 'Second guitar and the reason the setlist finishes on time.',
    xp: 0,
    appearance: {
      skinTone: '#d99e74',
      hair:   { style: 'wavy-mid', color: '#1f1a2e' },
      outfit: { style: 'tee', primary: '#232744', secondary: '#3f4a63', accent: '#8b5cf6' },
      shoes:  { style: 'sneakers-low', primary: '#e9e4dc', accent: '#8b5cf6' },
      accessories: ['lanyard'],
    } },
];
```

`id` is a stable slug — never reuse or rename one, because scores and claims
point at it. Roles: `vocalist`, `guitarist`, `bassist`, `drummer`,
`keyboardist`, `saxophonist`, `producer`, `core`, `member`.

## Moving your progress or your society

**Settings → Share**. Two codes:

- **The society** — everyone you added, no scores. Send it to whoever needs the
  full cast.
- **My progress** — your XP, badges and best scores. Paste it in on another
  device.

Importing never overwrites: XP only goes up and duplicates are skipped.

## How it's put together

One HTML file, read top to bottom:

| | |
|---|---|
| Pixel engine | integer-only drawing primitives, the character sprite, sheet caching |
| Data | the society, achievements, events, history, the map |
| Renderer | isometric tiles, buildings, depth sorting, the day/night wash |
| Games | Reso Rush, Reso Ludo, Reso Beat |
| Shell | save, HUD, panels, input, the main loop |
| Sound | one-shots, ambience per area, positional emitters |
| Wardrobe | unlocks and the gear that hangs off them |
| Online | claims, presence, the shared roster, board and table |
| Jam Room | the instruments |

Rules of the house, learned the hard way:

- **Data is separate from what draws it.** A member, an event, a room and a
  zone are all plain objects.
- **Game rules are pure functions.** They take state and return state, which is
  why the same `legalMoves` referees a pass-and-play move and an online one.
- **One of everything.** One XP system, one leaderboard, one interaction key.
  A second one is a bug, not a feature.
- **Everything degrades.** No network, no database, no sound, private browsing
  with no storage — the campus still opens and still plays.
